# 常见问题与排障

## 找不到搜索结果

依次核对当前/全局/目录范围、参与文件、正则和大小写、查询中有无首尾空格、结果模式、按文件起止行以及结果数量上限。空查询不等于匹配所有文本；“仅标记”模式不显示普通查询命中。

输入尚未提交或搜索尚未完成时，屏幕可能仍显示上一份正式结果。无效正则也会保留旧结果。页内查找与主搜索独立，Ctrl/⌘+Shift+F 不会替你切换到目录搜索。

## 日志在写入，界面没有跟随

确认窗口处于前台，日志是当前标签且完整索引已就绪，再确认末尾跟随是否开启。关闭跟随只停止滚到末尾；后台窗口和其他标签本来就不持续监测。

系统通知、400 ms 合并、正在进行的搜索、索引和画面准备都会增加延迟。网络盘可能依赖 30 秒复核；失败重试也有等待。怀疑中部改写未检测时按 F5 完整重建，详见[动态日志](https://github.com/zhaiyanqi/vclogg2/wiki/Live-Logs)。

## 乱码、Binary 或换行不符合预期

查看编码菜单中的检测结果，尝试“重新检测并加载”。Binary 模式按每行 16 字节展示十六进制。报告问题时说明文件原编码、BOM、换行形式，并提供脱敏字节样本；当前菜单没有任意手工选择编码的列表。

## 快捷键不生效

先离开输入框并点击目标日志区域。检查设置中的自定义绑定和冲突，核对 macOS 主修饰键、功能键与 Fn 映射。M 操作行标记，N 需要单条源行，W 切换换行。完整默认值见[快捷键](https://github.com/zhaiyanqi/vclogg2/wiki/Keyboard-Shortcuts)。

## 新构建看起来没有变化

核对“关于”中的版本和构建时间，以及实际正在运行的程序路径。同一数据根的单实例路由会把后续启动交给已有进程；已有安装版仍在运行时，新的命令行启动可能只是打开了它的新窗口。退出已有程序后再启动目标构建。

## 构建失败

确认使用 Rust stable、正确平台工具链、仓库根目录和锁文件。Windows 检查 MSVC/SDK；macOS 检查完整 Xcode 选择；Linux 核对原生开发库。Git 依赖下载失败时先确认网络，不要直接删除 Cargo.lock 来规避错误。[源码构建](https://github.com/zhaiyanqi/vclogg2/wiki/Building)提供命令。

## 安装或系统安全提示

从项目 Releases 获取正确平台包。当前 macOS 构建无 Developer ID 公证，Windows 是否签名取决于发布配置。文件名没有 unsigned 标识也不能证明已经签名；按系统提供的包来源与签名信息核对，不要关闭系统安全保护来替代验证。

## 云端过滤器不可用

核对服务地址与 `/api/v1` 兼容性、网络和会话。旧服务器缺少分支能力时写入口禁用；离线缓存只包含以前浏览过的公开页面。远程冲突需要明确处理，不应通过反复提交覆盖，见[云端过滤器](https://github.com/zhaiyanqi/vclogg2/wiki/Cloud-Filters)。

## 性能与诊断材料

大文件性能同时受行长、编码、命中密度、换行、磁盘与 GPU 影响。先记录文件大小/行数、编码、是否换行、搜索范围与上限、操作步骤和耗时，不使用单一历史基准推断本机结果。

“设置 → 高级”可选择应用日志等级并导出有界日志。Debug UI 耗时诊断仍有告警和汇总，但当前不再采集 UI 长任务调用堆栈；Rust panic 崩溃报告有独立回溯。生成测试数据和性能启动脚本见[使用指南](https://github.com/zhaiyanqi/vclogg2/wiki/User-Guide)；历史数字见[性能档案](https://github.com/zhaiyanqi/vclogg2/wiki/Archive-UI-Performance-2026-08-31)。

## 提交有效 Issue

提供程序版本、操作系统/架构、日志规模和编码、最小复现步骤、预期/实际行为，以及已执行的检查。对敏感日志使用脱敏样本；不要附状态库、Cookie、CSRF 或签名材料。入口：[GitHub Issues](https://github.com/zhaiyanqi/vclogg2/issues)。
