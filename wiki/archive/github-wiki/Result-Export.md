# 结果导出与时间合并

导出捕获点击时**完整的已提交结果集合**，不限于屏幕当前可见的几行；正在执行的下一次搜索不会改变已捕获快照。如果结果被数量上限截断，导出也只包含这份已提交集合。

## 三个入口

| 入口 | 输出与用途 |
| --- | --- |
| 保存… | 选择目标文件，将结果写到明确指定的位置 |
| 新标签打开 | 在应用临时目录生成结果文件，然后作为新日志标签打开 |
| 按时间合并 | 将跨文件结果按支持的行首时间戳稳定归并到新标签 |

结果工具栏和结果区上下文菜单按当前范围提供适用命令。普通当前文件导出按结果顺序写日志正文；普通全局导出按文件顺序分组，在每组前写完整路径标题，跳过空分组。

## 时间戳规则

识别行首 `MM-DD HH:mm:ss.1–6 位小数`，日期时间间隔也可使用 `T`。例如：

```text
09-08 14:25:03.120 service-a request started
09-08T14:25:03.120045 service-b request received
```

无时间戳续行优先继承同文件此前最近时间；首批续行必要时向后探测首个时间。相同时间按文件顺序和源行号保持稳定。输出不加文件分组标题。

该规则不等于通用日期解析器：不要假设任意 JSON 时间、时区、跨年日期或未排序源文件都会自动被正确规范化。保留原文件用于核对时间线。

## 保存行为

系统保存对话框取消后不创建文件。确认后先在目标目录写唯一暂存文件，写入与同步成功后再原子替换目标；失败保留已有目标。行标记圆点、颜色和文字标记属于展示层，不写回源日志或混入普通原文导出。

临时结果使用唯一 `vclogg2-search-*` 目录，不进入最近文件、会话检查点或启动恢复。需要长期保存时请显式另存为；不再需要的临时结果可在历史管理中移到系统废纸篓，其他窗口仍持有的文件会被保护。
