# 架构说明

VCLogg2 采用按能力分层的 Rust workspace：

```text
vclogg-app
├─ actions：桌面命令与键绑定
├─ app_log：运行时日志过滤、有界内存缓冲与快照导出
├─ crash_report：全局 panic hook、强制 Backtrace、本地报告落盘与有界保留
├─ single_instance：三平台单进程锁、命名管道/Unix socket 请求转交与启动参数编解码
├─ workspace：窗口、标签、焦点和后台任务编排
├─ log_table：日志与结果的虚拟化 DataTable delegate
├─ result_export：结果快照的流式写入、同目录暂存与平台原子替换
├─ state_store：SQLite/WAL 状态库与事务化最近文件访问
├─ color_labels：颜色标签定义、文件级规则序列化与预编译匹配器
├─ predefined_filters：UUID 分支模型、逐字段三方合并、查询段组合、兼容导入与 v5 JSON 导出
├─ predefined_filters_dialog：retained Input/Switch 草稿、单一二级路由、同步状态、冲突解决与后台文件选择任务
├─ search_autocomplete：顶层正则分支解析、历史/过滤器候选去重与当前片段替换
├─ selectable_log_text：StyledText 高亮与 Root 窗口文字选择协议的桥接元素及有界参与者缓存
├─ gpui-component 组件与主题化呈现
└─ vclogg-core
   ├─ document：有界安全预览、只读文件快照、强身份索引缓存、行起点索引与按需 UTF-8 解码
   └─ search：保留查询原文的普通多关键词和字节正则搜索
```

- `vclogg-app` 是应用外壳和界面呈现所有者，对外构建 `vclogg2`，不承载文件扫描算法。
- `vclogg-core` 是领域行为所有者，不依赖 GPUI，也不包含界面状态。
- `crash_report` 在任何单实例、窗口或后台任务初始化之前安装全局 panic hook。每次 Rust panic 都在本机应用数据目录的 `VCLogg2/crashes` 下以 `create_new` 写入独立报告，包含版本、平台、进程、线程、源码位置及不依赖环境变量的完整 Backtrace；报告刷新到磁盘后继续调用原有 hook，保留 Debug 控制台输出。目录不可用时回退系统临时目录，正常启动只保留最近 20 份。发行构建生成最小行号调试信息，交付脚本按版本生成独立符号包供开发侧崩溃分析留存；PDB 不进入用户分发包或安装目录。
- `app_log` 在其他运行时模块初始化前注册唯一 `log::Log`，以原子等级开关同时控制标准错误输出和内存收集。首次默认值由构建配置决定：Debug 为 Debug，Release 为 Error；用户设置写入 `app_settings` 并可选择 Off/Error/Warn/Info/Debug/Trace。缓冲按 20000 条与 8 MiB 双重上限淘汰旧记录，导出在后台抓取一致快照并写入带版本、构建和本地导出时间的文本文件。
- `StateStore` 在本机应用数据目录的 `VCLogg2/sessions/vclogg2-state.db` 使用 SQLite WAL。启动查询和写入都在后台执行；数据库不可用只降级持久状态，不阻塞打开日志。成功打开的多文件批次在单一事务内受路径唯一约束并递增 revision；每个标签另持有与当前界面对应的基准快照，检查点以 `BEGIN IMMEDIATE` 读取最新 revision。基准过期时只把“基准到本次界面快照”之间实际变化的字段覆盖到最新记录，然后在同一事务写入下一修订；回执仅以更高 revision 推进本窗口基准，且基准内容保持为本窗口已提交意图，从而不会把未呈现在本窗口的远端字段误当成本地后续编辑。可空 `custom_title` 随文件会话保存并由幂等字段迁移补入旧库，空值始终回退磁盘文件名。行索引缓存独立存放于系统缓存目录，不进入 SQLite 会话身份。
- 每个原生窗口拥有独立 `Workspace` 与 `Root`，共享同一 SQLite 状态库但不共享界面实体。单实例边界在 Windows 使用用户级命名管道，在 macOS/Linux 使用权限为 0600、父目录权限为 0700 的每用户 Unix domain socket；协议分别保留 Windows UTF-16 路径和 Unix 原始路径字节。后续启动不创建第二个 GPUI 应用：空路径请求创建新窗口，非空请求按注册表中的焦点顺序投递到最近激活窗口。Finder/桌面环境的文件 URL 也转换为同一 `OpenRequest`。若该 `Workspace` 正在打开或重载，外部路径在窗口内去重排队，任务结束后复用普通后台打开链路。关闭任一窗口都会先移除对应注册条目、同步抓取最终会话并排队保存。GPUI 使用最后窗口关闭即退出模式，不创建托盘图标或零窗口后台进程。唯一 `on_app_quit` 同步抓取全部仍存活条目的最新标签状态，先等待已关闭窗口和各存活窗口的既有写入，再按窗口创建顺序去重路径，最终用一个事务替换 `last_workspace_files` 并保存文件会话。启动只把该并集清单读入首个空工作区，用户选择单项或“全部打开”后才建立索引。
- 新窗口可接收不可变 `InitialDocument` 列表。标签复制在源 Workspace 同步抓取完整 `FileSessionState` 和临时路径属性；目标 Workspace 等自己的状态库 bootstrap 收敛后，把显式快照作为数据库会话的高优先级覆盖交给普通后台索引链路，因此不共享可变表格实体，也不依赖先写库再读库的竞态。目标重新执行已提交查询并原子安装恢复状态；源标签不卸载。
- 标签移动额外携带源 Workspace 弱引用、源窗口句柄、文档 ID 与捕获状态。目标安装结果通过源窗口上下文回传：失败不改变源；成功后再次从源表格实体派生完整 `FileSessionState`，只有逐字段相等才执行普通关闭链路。若传输期间源状态变化，移动安全退化为复制，避免目标旧快照覆盖或丢弃用户的新操作；每个源文档同时只允许一个未完成移动。发送到“另一窗口”时由注册表选择最近获得焦点的非源窗口，目标通过自己的 Workspace 接收；目标忙碌或同一路径已存在时使用延迟失败回执，避免嵌套更新源实体。
- 文件收藏复用 `file_sessions.pinned`，因此收藏身份与恢复会话一致，不维护第二份路径列表。收藏切换与清空都在后台写入并返回刷新后的收藏/最近快照；最近查询先按固定状态、再按最后打开时间排序。
- 历史清理以当前工作区路径作为运行时保护集合，并在同一事务内仅删除未固定、没有行标记的其余会话；外键级联修正持久化的上一次工作区清单，完成后界面原子替换收藏、上一次文件和最近文件三个查询快照。该操作只清理恢复元数据，不接触日志文件。
- 文件历史详情按用户命令从 SQLite 后台读取完整轻量摘要，不在启动 bootstrap 扫描全部会话。对话框实体独立拥有筛选输入、条目列表、行内删除确认和单一删除任务；删除提交点按数据库 ID 重新读取固定/标记状态，并与打开对话框时的工作区路径保护集合一起判定。成功后对话框和 Workspace 同步替换历史、收藏、上一次文件与最近文件快照，日志文件始终不在删除范围内。
- 应用日志等级、主题偏好、日志呈现默认值、搜索与滚轮策略等应用级选项保存在单行 `app_settings` 表，并通过幂等字段迁移兼容旧数据库。日志等级预览直接调整进程级过滤，取消设置会恢复打开前等级。主题、标签级视图覆盖、搜索开关、结果上限与关闭确认仍沿用各自既有真源和异步提交边界。正文、当前结果和全局结果的滚轮策略收敛到同一捕获入口：默认模式继续传播给 GPUI 原生像素滚动，自定义百分比或固定逻辑行模式在子表格消费事件前按真实当前位置计算目标并停止传播；换行列表用实测高度累计修正求行，固定表格用统一行高求行。正文收到普通垂直滚动后立即清除末尾跟随。相邻行预读取继续只围绕组件精确绘制范围维护有界解码缓存，不伪造行节点或改变选择、滚动锚点和减少动态效果语义。
- 颜色规则由 `DocumentTab` 按文件持有，并以 JSON 写入 `file_sessions.keyword_color_rules`；全局标签定义按稳定 ID 与顺序保存在 `color_labels`，独立初始化记录使空标签集合与首次默认状态可区分。管理对话框拥有名称 Input 与 ColorPicker 的 retained 草稿，保存后所有窗口按标签 ID 重新编译规则；表格 delegate 只接收不可变匹配器快照。正文、当前结果与全局结果复用同一快照，颜色标签覆盖主搜索，页内查找再覆盖两者；数据色是用户标签数据，不进入应用主题。
- 预定义过滤器以规范化 `FilterBranchId(UUID)` 作为唯一且不可变的身份，按顺序存放于 `predefined_filters`；SQLite 的 `filter_id` 与 GPUI `ElementId` 都直接使用 UUID，完整 v5 JSON 保存当前 `FilterSnapshot` 及按服务器隔离的远程引用集合。启动 bootstrap 兼容读取数组、Qt 和 v1–v4 JSON：合法旧 UUID 原样保留，只有缺失或非法时生成一次新 UUID；相同 UUID 才折叠并合并引用，不同 UUID 即使五个内容字段完全一致也并存。导入按 UUID 追加或三方合并，不删除导入文件未包含的本地项；导出固定为 v5。编辑对话框分别持有名称、匹配值和备注 Input 实体，第一层 Dialog 始终渲染列表，`FilterBranchId` 选择详情；本地详情、云端只读详情、首次分享和逐字段冲突处理收敛为单一二级路由，共用标准 Dialog、滚动边界、`Esc` 关闭和原触发焦点恢复。云端下载、快进与安全合并在替换本地集合后立即发出保存事件，并在重建本地草稿时保留当前二级路由，避免留下内容为空但仍占用对话框栈的模态层。提交只校验必填字段，不再按名称、内容或类型判重；事务替换、跨窗口修订屏障和退出落盘规则保持不变。查询执行仍以完整表达式段避免重复追加，因为重复执行同一段没有意义，但该优化不参与实体身份、持久化或同步判断。搜索补全继续只拆顶层 `|`，其候选去重同样只影响一次查询输入，不合并过滤器实体。
- 云端过滤器客户端与 UI 状态分离：`CloudClient` 在线程安全核心中持有阻塞 HTTP 客户端与一次 401 续权逻辑，GPUI 实体只保留可取消生命周期内的后台任务和不可变 DTO。客户端 UUID 原子写入应用数据目录，服务器地址和显示名称作为公开偏好进入 SQLite，Cookie 与 CSRF 组合只保存到按规范化服务器地址哈希分帐的系统凭据库；公开 profile 不写秘密。首次注册直接提交 UUID 与显示名称，不再读取、校验或嵌入 Ed25519 客户端密钥，也不发送旧客户端使用的密钥 ID、时间戳、nonce 或签名请求头；部署端必须允许未签名的注册请求。
- 设置对话框的“网络”分类只是上述云端能力的配置入口，不持有第二套客户端或秘密状态。服务器地址与用户名由 retained `InputState` 保存草稿；“保存并测试”先发布公开 `CloudSettings` 供 Workspace 写入 SQLite，再以对话框生命周期内的后台任务调用共享 `CloudClient`。成功结果会用规范化地址和服务器确认的显示名称回填输入并发布 `CloudConnectionProfile`，失败只更新就地状态；Cookie/CSRF 从不跨越客户端边界进入 GPUI 实体。空用户名优先以当前系统用户名初始化，地址则按 SQLite、既有公开 profile、构建默认值的顺序恢复。
- 设置分类选择是独立的界面导航状态，不进入可取消的设置草稿。`WorkspaceWindowRegistry` 在多窗口间共享当前分类，`ui_state` 表按稳定分类标识持久化；普通“设置”入口恢复该分类，“帮助 → 关于”显式覆盖为“关于”并成为新的最近分类。“高级”分类在所有平台提供应用日志等级与导出，不再执行运行时注册表读写。“关于”把构建脚本注入的 Unix 时间戳转换为运行机器本地时区并带偏移显示。
- 本地和远程 UUID 相同时才表示同一逻辑分支。跟踪引用保存服务器、相同远程 UUID、已知修订、所有者与共同基线；派生引用只表达谱系，不参与去重。同步状态由当前、本地基线和远程快照纯派生为未下载、已同步、本地有修改、远程有更新、可自动合并、存在冲突、远端已删除或协议不支持。三方合并对名称、匹配值、正则、备注和共创状态逐字段处理：一侧未偏离基线时采用另一侧，两侧结果相同时直接采用，只有同一字段双方不同改动才冲突；无共同基线、修订倒退或同修订内容不一致按异常冲突处理，绝不覆盖本地。批量下载先应用快进和无冲突合并，再按原顺序进入同一二级冲突页面；“稍后处理”保持该分支不变。合并只更新本地内容和远程基线，不自动提交；已有跟踪分支必须通过“提交本地修改”携带 `baseRevision` 更新，首次分享只接收尚未发布的分支。“另存为新过滤器”生成新 UUID、保留派生来源并清除同分支跟踪。云端详情字段全部只读，历史修订只“恢复到本地”；远端删除保留本地分支并解除对应引用。服务器返回结构化 `revision_conflict/currentRevision` 后，客户端重新读取远端并进入相同三方合并流程，不以错误字符串判定，也不自动重试覆盖。
- 云端服务器通过注册和 `/api/v1/me` 的 `filter-uuid-branches-v1` capability 声明 UUID 分支协议。新客户端把本地 UUID 作为 `clientFilterId`；支持协议的服务器用它作为远程主键，同所有者按基线修订更新、其他所有者返回身份冲突，同 UUID 同内容保持 `no_changes`。未声明 capability 的旧服务器仍可浏览、缓存和下载，但客户端禁用首次分享与远程提交。服务端继续接受非 UUID `clientFilterId` 的旧客户端流程；内容相同但 UUID 不同的记录在普通和管理员路径都允许共存。
- 更新客户端在三平台发行构建中启用，并与云端业务 Cookie 完全隔离。HTTPS 客户端同时加载 WebPKI 内置根证书与操作系统信任库，使公共证书链和已由系统管理员信任的企业代理 / 私有 CA 都能通过标准校验；证书或主机名验证不会被降级或跳过。默认源是 `zhaiyanqi/vclogg2` 的 GitHub 最新正式 Release，不要求服务器设置：先读取 REST 元数据，按目标选择 `latest-<platform>-<architecture>.json`，再交叉验证 `v<SemVer>` 标签、产品、平台、架构、资产名称、大小及 GitHub 可用的 SHA-256 摘要。Release 浏览下载地址必须精确属于目标仓库、标签和文件名；仅 GitHub 资产客户端可在最多五跳内跟随到 GitHub 管理的 HTTPS 域名，普通静态源继续禁用重定向和账号 URL。已配置服务器时，自建源按根地址派生 `/updates-vclogg2/<platform>-<architecture>/` 并作为第二来源；一侧失败时沿用另一侧结果，两侧都有更新时选择较新 SemVer。artifact / blockmap 必须是单段文件名；客户端检查包大小、1 MiB 分块数量和所有 SHA-256。下载写入版本专属目录的 `create_new` 暂存文件，每个分块即时验证，整包刷新并同步磁盘后才在同目录改名为可安装包。更新清单不做独立数字签名，SHA-256 用于发现传输损坏或清单与文件不一致；默认源真实性依赖 GitHub 仓库权限和 HTTPS，自建源依赖部署侧访问控制和 HTTPS。
- 更新安装不从 GPUI 进程覆盖自身。用户确认后，Windows 启动系统 PowerShell 助手，macOS/Linux 启动随二进制编译的 POSIX shell 助手；标准输出/错误都写入更新目录日志。助手等待当前 PID 结束，在唯一临时目录解压，再经包内平台安装器原子替换当前安装：Windows 更新程序、开始菜单和“打开方式”，macOS 更新 `.app` 并刷新 Launch Services，Linux 更新用户级程序、desktop/MIME 与图标。GPUI 随后调用正常 `quit`，因此多窗口 Session flush 仍是安装前的一致性屏障。跨平台发布脚本先复制版本化包和 blockmap，最后原子替换 `latest.json`，使新清单只引用已经落盘的文件。
- 关闭标签会同步生成带版本号的 `TabResumeState`：正文选择与正文视口分离保存；视口以首个可见源行、该行顶边相对视口顶部的像素位置、横向偏移和末尾标志表达；当前文件结果另存可见性、稳定源行选择、结果下标回退和独立视口；活动区域、末尾跟随及标签级自动换行一并进入同一快照。重新打开在任何文件 I/O 前先用路径和显式空 `LogDocument` 同步注册稳定 `DocumentTab`、TableState 与虚拟列表实体；后台优先用严格验证的缓存偏移读取保存视口锚点前后最多 200 行，缓存不可用才读取最多 1 MiB / 200 行的安全头部预览，再建立完整索引并在同一实体中依次换入。分段预览只持有该窗口正文，但 `segment_start_row` 让表格选择、标记、行号与会话始终使用全局源行号。打开中或预览标签关闭后，后续结果必须同时匹配路径与文档 ID 才能提交。会话选择、标记和恢复快照在预览范围外时保持待恢复，完整文档和已提交查询结果都安装后只经过一个 `apply_tab_resume` 入口恢复，不再用选中行居中代替视口；旧会话由 `selected_row` 与查询文本迁移为兼容快照。关闭写入在窗口内严格串行，后一提交以同一路径前一回执作为合并基准；立即重开优先使用尚未落盘的最新内存快照。完整阶段失败会保留可浏览预览并允许重新加载；搜索、页内查找、按行定位、末尾跳转和跟随只接受 Ready 文档。
- 当前文件、全部打开文件和目录搜索是三个独立的结果上下文。当前文件上下文属于 `DocumentTab` 并随文件会话持久化；全部打开文件与目录上下文在运行时分别持有结果与匹配器，并将查询、结果模式、可见性、上下文级自动换行、目录选项、分组折叠、按路径压缩的源行选择、活动稳定行和视口锚点写入版本化 `WorkspaceSearchState`。全局和目录范围允许空查询：匹配器为空、匹配集合为空，显示集合仍由结果模式是否包含同路径打开标签的标记决定。目录后台只保留有匹配或与打开标签同路径的候选快照，安装到表格前剔除零行分组。搜索范围只选择一个上下文投影到共享全局结果表，离开范围时捕获、进入范围时恢复；进程重启后不保存可能巨大且过期的结果文本，而是按原查询惰性重扫当前被访问的范围，再以文件路径和源行稳定身份恢复呈现状态，锚点失效时才退回保存的结果下标。因此三个范围不会互相覆盖，且文件内容变化时不会展示旧结果。
- 自动换行的所有权跟随结果上下文：正文和当前文件结果使用各自 `DocumentTab.word_wrap`，全部打开文件与目录结果各自使用 retained/persisted `word_wrap`。切换标签、搜索范围或重开应用只恢复目标上下文自己的值，其他文件或搜索范围后续切换自动换行不会污染它。
- 行选择、搜索提交/清除、结果模式、标记和呈现选项变化会替换当前窗口唯一的延迟任务；活动状态连续 1.5 秒不再变化后才抓取并写入检查点。切换标签和关闭标签仍即时抓取旧标签，避免合并任务取消时丢失最后状态。
- `Root` 是每个窗口唯一的顶层组件，统一负责弹层、通知和焦点恢复。标题栏提供常驻清除按钮并调用当前窗口 Root 的批量关闭链路，不影响其他窗口。
- 设置对话框打开后以自己的 retained 后台任务读取系统索引缓存目录，只枚举 `.vclog-index` 与严格命名的暂存文件。手动清理先捕获路径、大小和修改时间，删除每项前重新读取 metadata 并只删除完全未变化者；清理与正在完成的原子缓存写入可以并发，变化或占用文件安全保留。目录揭示先后台创建目标目录，再调用 GPUI 平台能力，不经过 Shell 字符串拼接。进程级原子门保证启动后只调度一次延迟自动维护；普通缓存超过 90 天、暂存超过 24 小时会进入候选，再按最旧优先把普通缓存压到 512 MiB，所有删除仍复核原快照。
- Windows 二进制通过包级 `build.rs` 只为 `vclogg2` 链接目标预留 8 MiB 主线程栈。GPUI 首帧会在平台主线程构造完整的类型化元素树，默认 PE 栈预算不足会在窗口首次渲染时溢出；扩大的是虚拟地址预留，不改变业务任务的后台执行边界。
- 可重复日志行、标签页和结果项使用文件身份与源行号构成稳定身份，不使用可变列表下标作为长期身份。
- `LogDocument` 是后台建立后原子安装的只读快照；界面只在 DataTable 请求可见行时解码正文。安全预览的映射长度受字节和行数双重限制，但 metadata 保留源文件真实大小；一条超长首行最多显示 1 MiB，不会为寻找换行越过边界。编码检测按 BOM、已知二进制签名、无 BOM UTF-16 启发式、控制字节、UTF-8 与 chardetng 传统编码依次决策；LF、CRLF 和独立 CR 均由同一编码感知分行器建立偏移，文件以换行结束时保留末尾空行，UTF-16 使用双字节分隔符，Binary 使用固定 16 字节行。显示、搜索、高亮和导出都从同一快照解码，避免视图与搜索语义漂移。完整索引以系统缓存目录中的原子文件持久化，行起点按递增差值 varint 压缩；只有文件大小、修改时间及平台强身份全部一致时才复用：Windows 使用卷序列号、128 位文件 ID 与 USN，macOS/Linux 使用设备号、inode 与 ctime。缓存缺失时先发布完整文档，再由后台任务写入共享行起点 Arc，不复制正文。行索引同一次顺序扫描记录最长字节行与最长显示列：UTF-8 沿用旧版的字节列语义，制表符推进到下一个 8 列制表位，首行 BOM 和行尾 CR 不占宽度；非 UTF-8 文本按解码字符计算显示列。纯增长增量路径当前只接受 UTF-8 / UTF-8 BOM，其他编码回退完整重建。空文件使用显式空快照，后续增长可进入与普通日志相同的刷新流程。
- 搜索范围由 Workspace 在当前标签、多标签和目录之间单点拥有。目录配置保留根路径、文件后缀过滤的启用状态与表达式、递归及隐藏目录策略；多个后缀以 `|` 分隔并按大小写不敏感的文件名末尾匹配，关闭过滤时接受所有文件。枚举拒绝符号链接递归并隔离不可读目录。候选路径通过与普通打开相同上限的准备工作线程创建临时 `LogDocument`，共享一次编译的匹配器和协作取消令牌，只把实际命中文档原子安装到全局虚拟结果。临时结果使用与标签 ID 不相交的高位身份；点击结果后按路径复用普通打开链路，完整索引到达时再提交源行定位，因此目录扫描不会制造标签或文件会话。
- `TableState<LogTableDelegate>` 继续拥有固定行高虚拟化与纵横滚动，但不再拥有日志的可见当前行样式：delegate 内的 `LogTableCursor` 保存当前虚拟行，Workspace 按区域焦点完成键盘导航，再借用 TableState 滚动句柄定位。每次指针、键盘或结果跳转仍通过 TableEvent 交付一次语义选择，随后在同一次更新中清除组件内部整行选中态；压缩 `RowSelection` 保持不变并作为正文列选区的唯一绘制来源，因此单选与多选不会再把标记列或行号列染色。delegate 使用所选等宽字体在 GPUI 文本系统中的实际 `ch` advance 与索引最长显示列生成消息列宽。正文、当前结果和全局结果各自保留独立 FocusHandle、压缩行选择与滚动状态，`LogRegion` 是窗口级命令归属的唯一真源；鼠标按下、Tab 聚焦和结果跳转更新该归属，复制、全选、标记、颜色标签与页内查找不再从搜索范围推断目标。普通日志页面的文字参与者统一注册到 gpui-component Root 实际激活的默认文字作用域；区域隔离由真实指针命中、独立 FocusHandle 和 `LogRegion` 完成，不创建只会被 Root 普通页面忽略的自定义作用域。重复行使用 `LogRowKey`（文档 ID + 源行；全局文件标题使用文档 ID）作为稳定身份，不把可变表格下标持久化。
- `GlobalSearchTableDelegate` 复用同一 `RowSelection` 压缩区间状态机，组标题只占虚拟布局槽而不成为领域选择。状态栏用区间长度减组起点数量计算选中行数，`Ctrl+A` 因此不会为百万级结果逐行计数；真正复制或命令提交时才按平铺位置映射为 `(document_id, source_row)`。结果模式、标记和颜色规则引起重组前，delegate 把选择压缩为每文件 `CompressedRows`，重组后只恢复仍可见的源行。整行复制保持当前分组顺序，批量标记按文件更新各自 Session；颜色标签先验证所有源行属于同一文件，拒绝跨文件含混修改。
- 行选择在鼠标按下时保留锚点、是否合并以及按下后已提交的范围快照。DataTable 的鼠标松开选行入口在三个日志区域统一关闭；行元素在按下时只提交一次当前行与结果跳转，后续移动只能由 Workspace 手势状态机修改压缩范围，避免松开阶段再次滚动、覆盖 `Ctrl`/`Shift` 锚点或让结果行重复跳转正文。无修饰双击把当前行收敛为单行并交给文字选词，无修饰三击只保留所属整行。无修饰键的单击拖动先处于文字模式，同一逻辑行内完全交给 `TextSelection`；固定表格与自动换行列表都在 prepaint 保存实际渲染行边界，指针真正命中第二条逻辑行时才切到整行模式，不再通过首行下标、估算行高或滚动余量反推目标行。切换后保留但暂不绘制底层文字投影，并从原始行锚点扩展压缩范围；拖回实际起始行会恢复按下快照并重新显示仍持续更新的原生文字端点，再次跨行仍可重入整行模式。若在整行模式松手，窗口捕获阶段会清除隐藏的文字选区，避免后续复制抢占整行范围。`Ctrl`/`Shift` 在按下时抑制文字选择并直接使用整行语义。`SelectableLogText` 的 retained 参与者另保存当前投影与可选自定义范围：双击时用布局命中的 UTF-8 偏移、Unicode 空白和应用级边界字符计算词范围，通过参与者本地选择与 copy callback 保持绘制、复制和颜色标签的同一权威范围；普通窗口几何选择仍沿用投影范围。Workspace 只在对应表确实处于行拖选时记录最新指针与预绘制视口边界；指针进入上下 32px 边缘后启动唯一 40ms retained 任务，按越界距离每拍移动 1–8 个逻辑行、推进固定表格或自动换行列表的唯一滚动所有者，并把终点扩展到新视口边缘。任何窗口级左键释放、标签关闭或实体失效都会清除任务和拖选状态。
- 文件会话的 `word_wrap` 默认关闭。关闭时正文、当前结果和全局结果各自在 DataTable 底部以同级区域承载常驻横向滚动条，轨道与表格视口等宽且不覆盖数据行；轨道直接汇总表格列定义取得包含固定列的完整内容宽度，不依赖虚拟行预绘制后才可用的滚动句柄测量，因此首帧即可确定是否溢出，最大偏移仍与消息画布一致。开启后，三个区域保留各自 `VirtualListScrollHandle`、尺寸向量与文字选择缓存，并用 gpui-component `v_virtual_list` 作为唯一滚动所有者；`TableState` 继续充当选择、领域映射和命令事件模型。尺寸向量先以“字号 + 行距”常量估算全部逻辑行，只为虚拟视口附近解码并排版文本；`SelectableLogText` 在 prepaint 回报真实多行布局高度。逻辑滚动条的 `set_offset` 会标记一次同步测量请求，下一帧先测量目标视口并提交尺寸，再构造可见行，从而不以旧基础高度绘制重叠文字。自动换行切换与后续实测继续按稳定行及其相对顶部像素恢复同一视口锚点；内容重组仍使用带末尾状态的 `ViewportAnchor`，实测行保持最多 4096 项的有界缓存。
- 标记、颜色规则、搜索结果和结果模式修改都在单次 Workspace 更新中捕获选择/视口、生成不可变标记与高亮快照、更新三个区域 delegate、恢复稳定身份后统一通知。菜单栏、标题栏、快捷键和标准 ContextMenu 复用同一领域方法；PopupMenu 只持有打开时的稳定文字或行上下文，文档/结果失效时由领域方法再次校验并安全退出。A051 是始终存在的独立标记列：搜索命中使用 danger 实心标记，用户标记使用 warning 实心标记，两者重叠时由同一圆内 135° 红黄分区表达，光晕与轮廓沿用同类主题 token。选择背景只覆盖正文列；单行具有完整上下边界，相邻多选压缩为不含内部边界和行分隔线的连续段，离散范围各自成段。页内查找、颜色标签、已提交搜索保持严格覆盖优先级，日志级别只提供弱行背景。
- 换行尺寸状态同时从最多 4096 个实测行构建按行排序的累计高度修正，前缀高度和指针命中通过二分定位而不从文件头线性扫描。尺寸提交前抓取“首个逻辑行 + 行内像素偏移”，提交后按新前缀恢复同一锚点。覆盖在同一 `VirtualListScrollHandle` 上的 `LogicalVirtualScrollHandle` 向 gpui-component `Scrollbar` 暴露固定的 `逻辑行数 × 基础行高` 轨道，并在读取/拖动时以当前行内比例双向转换真实像素；精确末屏单独映射实际最大偏移，因此新测量不会改变已抓住滑块代表的逻辑位置。
- 标签命令菜单由触发标签的文档 ID 闭包绑定，不读取可能在菜单打开后变化的活动下标。标签正文的 `ContextMenuExt` 命中层与省略号按钮复用同一个 PopupMenu 构建器，保留组件的焦点恢复且不遮挡后缀按钮。批量关闭先同步捕获目标标签会话，再一次过滤文档、全局参与集合和已提交全局分组；活动标签仍存在时按 ID 恢复，否则按关闭前索引夹取相邻标签。路径复制与平台文件揭示同样只按触发文档 ID 解析。
- “关闭并删除文件”从同一触发文档 ID 捕获磁盘路径，经危险 AlertDialog 明示文件名、完整路径和系统废纸篓语义。确认先走普通关闭链路保存最终 Session 并卸载持有只读映射的文档实体，再延迟一帧于后台调用平台废纸篓实现。普通文件校验发生在系统调用前；成功或文件原本不存在后才按路径删除 SQLite Session 并重读最近、收藏与 Workspace 清单。废纸篓操作失败只通知且保留已保存 Session，避免把“标签已关闭”误报为“文件已删除”。
- 标签自定义名称由 `DocumentTab` 持有并通过同一 `FileSessionState` 检查点持久化；显示标题是自定义值或磁盘文件名的单一派生结果。重命名与恢复在一个提交中同步标签、活动窗口标题和已有全局结果组标题，不改变文件身份、路径或搜索快照。
- 窗口内标签拖放负载只携带稳定文档 ID、显示标题、源 Workspace 弱引用与预览位置；`Workspace` 是顺序的唯一写入者。放置时先按 ID 移出并插入目标槽，再按活动文档 ID 重算下标，同时重排已提交全局结果组；文档实体、索引快照和表格状态不重建。Windows 后端在鼠标按下后调用 `SetCapture`，因此源窗口会继续收到视口外的拖动与松开事件；跨窗口协调器把源局部坐标乘源缩放比转换为物理屏幕坐标，再按各目标窗口缩放比换算局部坐标，与 prepaint 记录的标签边界求插入下标。若释放点不在任何 VCLogg2 窗口内，则按 GPUI 显示器边界在释放点附近创建可见的新窗口，并继续使用同一成功回执协议。目标窗口只接收完整 `InitialDocument`，真实日志路径不会成为系统拖动负载；取消、源窗关闭和应用退出都会清除目标提示而不卸载源标签。新顺序通过 `save_workspace` 的单事务路径立即保存，退出 flush 仍作为最终一致性屏障。
- 行号与正文分隔线属于标签页呈现状态，由同一视图选项快照同步到正文和结果两个 DataTable delegate。隐藏行号会重建列布局，但不改变源行身份或选择；分隔线只使用主题边界 token 绘制在正文单元格中。
- 行号栏几何与颜色属于应用级外观：40–160px 是旧版可配置物理列宽契约，不随日志字号缩放；可空的 `#rrggbb` 用户颜色在渲染时回退到当前主题的弱前景与低对比度底色。固定行高 DataTable 和可变行高虚拟列表都让正文分隔线只属于正文单元格、独立行号分隔线只属于行号单元格，并同步覆盖日志、单文件结果和全局结果。
- 行标记由对应 `DocumentTab` 持有源行号集合，正文与结果表 delegate 共享不可变快照；单行和多行标记使用同一个批量语义：目标全部已标记时统一取消，否则补齐未标记项。重新加载时会剔除超出新文件范围的标记。结果模式同样属于标签页状态，由单一派生步骤将有序匹配行与标记行合并、去重或筛选，再原子刷新结果表，并按仍存在的源行恢复结果选择。
- 打开和搜索由 GPUI background executor 执行；搜索扫描持有显式取消令牌和共享一致性进度快照，新任务、清除、重新加载或关闭文档会中止失效扫描。窗口在搜索期间按固定间隔采样快照且只在数值变化时刷新，完成时再通过文档 ID / 全局轮次 revision 拒绝迟到结果。
- 已提交搜索命中以共享 `RoaringTreemap` 保存源行号；结果模式把用户标记直接并入新的压缩集合。单文件表通过 `select` 把虚拟行映射为源行、通过 `rank` 恢复选择；全局表仅保存每个文件组的累计起点，按需计算组头或压缩集合中的结果行，不再构造与全部命中数量等长的 `FlatRow`。全局页内查找只克隆每组文档和压缩集合，导出按迭代器逐行解码，因此搜索完成后不会在 Workspace、表格、查找和导出层重复展开命中数组。
- 全局结果重组前同时捕获首个可见逻辑行的稳定身份和被视口裁掉的像素余量；新分组安装后先映射稳定身份，再用 gpui 虚拟列表的统一行高还原绝对偏移。若首行已被过滤则回退到所属分组标题，若尚无布局测量才回退为严格顶对齐。
- AppShell 是外部文件拖放的单一命中区域；平台 `ExternalPaths` 在界面提交点过滤文件夹并保留原顺序，然后直接进入与文件选择器相同的 `begin_open_paths` 后台准备和原子安装流程，不维护第二套拖放专用文档状态。`Workspace` 只保留窗口级覆盖层可见状态；零绘制 Canvas 在 paint 阶段按 GPUI 契约注册下一帧 `FileDropEvent` 监听，并由 `Entered / Exited / Submit / Ended` 精确切换状态，拖动停留不会超时消失，离开、取消或提交也不会遗留覆盖层。
- 主进程只在进入 GPUI 事件循环前读取一次 `args_os()`；可执行文件之后的路径按原顺序转换为不带显式会话覆盖的 `InitialDocument`，待首个 Workspace 的状态 bootstrap 完成后复用普通打开链路并查询已有会话。跨窗口复制/移动仍携带显式会话快照作为高优先级覆盖。命令行、文件关联、文件选择器、最近记录、拖放和跨窗口传输最终共享同一加载状态机与迟到结果校验。
- 全局搜索以提交时的已打开标签顺序捕获不可变文档快照，每个文件在线程作用域内并发扫描，界面只汇总进度。可见全局分组与后台待提交结果双缓冲：任何文件完成都不发布部分分组；全部文件结束后才一次替换 `GlobalSearchTableDelegate`。取消、无效正则、关闭目标文件或新轮次到达都保留上一份完整结果。
- 全局搜索参与集合在运行期由 `Workspace` 以文档 ID 持有，选择对话框只编辑 retained 草稿，确认后与当前标签集合求交并一次提交；同时按规范化文件路径把每个已见文件的布尔偏好幂等写入 SQLite。再次打开已见文件时恢复其偏好，未知新文件默认加入；关闭文档同步移除运行期 ID，提交搜索时只按标签顺序捕获已选择文档，空集合显式禁用执行。
- 全局结果 delegate 把文件标题与展开的源行扁平为一个 DataTable 虚拟索引空间。文件 ID 和源行号构成稳定行身份；标题行只改变本组折叠状态，命中行通过文件 ID 激活标签并定位源行。`Workspace` 独立保留每个参与文档的原始匹配集合；全局结果模式或 Session 标记变化只重组显示集合，不重新扫描。重组前捕获选中领域行、首个可见领域行及其像素余量，提交后按文件 ID/源行映射，并用虚拟列表行高还原精确偏移。
- 结果导出在界面提交点捕获不可变 `LogDocument` 与源行号集合，后台逐行解码并写入固定容量缓冲，不把全部结果正文聚合到内存。当前文件只写日志正文；普通全局结果按已提交标签顺序写非空分组，并以完整路径作为组标题。时间戳合并为每个文件维护一个游标与最近已解析时间，行首按无时区的月日、时分秒、微秒打包；续行先在上个结果之后反向寻找时间戳，再继承游标时间，仍未知时向后探测。最小堆只持有每个文件当前一行，以时间戳、标签顺序、源行号稳定归并且不写分组标题。用户目标先在同目录创建唯一暂存文件、刷新并同步到磁盘，Windows 已有目标由 `ReplaceFileW` 原子替换；失败清理暂存文件且不破坏旧目标。新标签命令在唯一临时目录完成同一写入协议后才进入普通索引/标签安装链路，临时路径由 Workspace 排除在最近文件、会话检查点和退出恢复之外。
- 临时结果生命周期不依赖 SQLite：文件历史后台只扫描系统临时目录直属且名称为 `vclogg2-search-*` 的目录和普通文件，形成轻量路径/大小/修改时间快照。打开保护集合从应用级窗口注册表汇总所有 Workspace，而不是只查看发起对话框的窗口。单项与批量清理在提交点再次限制为该临时路径形状，再逐文件调用系统回收站；成功后仅以非递归方式删除空父目录，避免清理命令扩大到临时根或其他应用数据。
- 文件历史的数据库摘要在状态库互斥锁内执行一次被动 WAL checkpoint 和 `file_sessions` 计数，释放连接锁后再读取主库、WAL 与 SHM 三个明确 sidecar 路径的 metadata 并饱和求和；统计不扫描日志文件或索引目录，也不让缺失的瞬时 sidecar 阻断历史对话框。
- 文件关联不再由设置页运行时修改。Windows 当前用户安装器注册 `Applications\vclogg2.exe`、专用 ProgID、`RegisteredApplications`/Capabilities 及六种扩展名的 `OpenWithProgids`，但不写 `UserChoice`；macOS `Info.plist` 声明同一组文档扩展并由 Launch Services 注册；Linux 安装器写入用户级 `.desktop`、图标与 MIME 列表。三者传入的路径或文件 URL 都复用单实例转交和普通打开状态机。
- 自定义打开目录命令同样不经过 Shell 字符串：设置页只持久化最多 2048 个字符的原始命令，提交时由应用内解析器识别单/双引号边界，把首项作为可执行文件、其余项作为 `Command::args`，再替换目录和文件占位符；没有占位符时只追加一个目录参数。子进程以目标目录为工作目录、关闭标准流并在 Windows 隐藏控制台，解析或启动错误回到触发窗口通知。空设置仍使用 GPUI 平台的系统打开能力。
- 云端公开目录缓存位于应用数据目录的 `cloud/directory-cache`，文件名由标准化服务器 URL 的 SHA-256 派生，内容只含公开过滤器 DTO、查询/排序分页键与抓取时间。在线目录成功优先返回真实响应，缓存写入失败不会遮蔽结果；网络或服务请求失败才读取缓存。离线读取对所有保留分页按 UUID 与修订去重，在本地执行查询、排序和分页，并把界面切成显式只读状态；缓存只允许下载或合入严格晚于本地基线的修订，不能写远程，也不能回退本地基线。会话 Cookie、CSRF 及草稿从不进入该缓存。
- 成功搜索会把与扫描器同源的已编译 `SearchMatcher` 安装到正文和结果 delegate。虚拟表只为当前绘制行计算非空 UTF-8 字节范围，并用 GPUI `StyledText` 与主题警告 token 呈现；仅标记但未命中的结果行不会产生高亮。日志级别检测同样只发生在当前绘制行，按旧版优先级匹配 ASCII 单词边界：错误类高于警告、信息和调试类；表格行使用主题 danger、warning、info 或 muted token 生成弱背景，不占用独立标记列。选择背景只覆盖正文列，用户标记始终由标记列表达。全局结果 delegate 复用同一检测器，避免三个视图语义漂移。
- 末尾跟随是每个标签独立保存的显式状态。窗口只对当前活动、完整索引就绪且开启跟随的文档做低频元数据采样；文件变化后把旧快照交给核心刷新。完整文档建立时除头尾各最多 64 KiB 的快速样本外，还保存旧前缀每 4 MiB 的 SHA-256；只有新文件更大、快速样本一致且全部旧前缀块逐一匹配时，核心才复用旧行起点并只扫描新增字节。任一中间块改写、截断、替换或读取边界异常都回退全量重建；成功追加形成的新快照重新计算覆盖完整新文件的分块摘要。两条路径都在后台形成新快照并通过文档 ID 与 revision 拒绝迟到结果，界面最后原子发布、恢复查询并定位末行。手动 `F5` 始终全量重建；用户把正文视口移离末尾或点击结果导航时关闭跟随。持久索引复用已有强文件身份。
- 主题颜色、字体、间距和控件大小全部来自 `cx.theme()`、rem helper 或组件 Size API。窗口初始物理尺寸是唯一经过说明的固定像素边界。
