# 架构说明

VCLogg2 采用 `core / data / app` 三层、按能力继续分区的 Rust workspace。依赖只允许从上层指向下层或稳定边界，禁止反向依赖：

```text
vclogg-app                    # GPUI 应用外壳、展示状态与交互编排
├─ workspace                  # 窗口、标签、焦点和后台任务编排
├─ log/global_search_table    # 虚拟列表、选择、高亮、行高和换行呈现
├─ dialogs/actions            # 对话框、桌面命令与键绑定
└─ presentation               # 主题、文字选择和界面性能状态
        │
        ├───────────────┐
        ▼               ▼
vclogg-core          vclogg-data
# 文件与搜索逻辑       # 持久化与缓存生命周期
├─ document           ├─ index_cache lifecycle
│  └─ index_cache     │
├─ search             ├─ path_codec
├─ result_set         ├─ state_repository
└─ cancellation      └─ state DTO / path_codec
```

- `vclogg-core` 负责文件读取、行索引建立、搜索执行与结果集合运算；`result_set` 独立维护压缩行集合、集合拼接、位置区间和稳定源行映射。core 不依赖 GPUI，也不包含持久化或界面状态。
- `vclogg-data` 负责 SQLite 持久化、缓存生命周期和可恢复状态的存取；它不依赖 GPUI，也不决定界面如何呈现这些状态。
- `vclogg-app` 是应用外壳和界面呈现所有者，对外构建 `vclogg2`；用户高亮、选择、选词、字号、行高、换行、标记与交互状态都在这一层组合，渲染路径不直接执行文件 I/O。
- `workspace.rs` 只保留窗口级组合入口；窗口注册、跨窗口标签拖放和退出快照位于 `workspace/window_registry.rs`，文件选择/拖放/最近/恢复入口、外部路径队列和会话覆盖位于 `workspace/document_opening.rs`，会话快照/检查点、文档安装与恢复、加载升级、重载和末尾跟随发布位于 `workspace/document_lifecycle.rs`，复制/全选/编码/跳行、标记与颜色、搜索焦点、窗口命令和标签显示开关位于 `workspace/document_commands.rs`，收藏/历史界面、设置预览、颜色/过滤器/云端偏好、外观保存和字号滚轮位于 `workspace/preferences.rs`，标签预热激活、关闭、排序、跨窗口传输和显示名称重命名位于 `workspace/tab_lifecycle.rs`，页内查找的匹配器、高亮、可取消扫描、源版本校验和视口定位位于 `workspace/quick_find.rs`，已提交的本地/全局/目录搜索范围、历史与恢复、任务派发、结果安装和清理位于 `workspace/search_orchestration.rs`，行高与换行模式、原子滚动帧、可取消可见行装入、视口所有权和键盘导航位于 `workspace/viewport_orchestration.rs`，标题栏、标签栏、搜索控件和空工作区外壳位于 `workspace/render_shell.rs`，可见日志与结果渲染、高亮合成、选词/选行、拖选、上下文动作、换行表格和视口锚点位于 `workspace/log_presentation.rs`，后台文档准备与结果快照算法位于 `workspace/document_tasks.rs`，不可变结果投影的保存、时间戳合并和新标签打开编排位于 `workspace/result_export_flow.rs`，滚动、结果快照和文档准备回归分别位于同目录测试模块。新增 workspace 能力必须进入命名子模块，不再扩张单体文件。
- app 可以组合 core 与 data；core 不依赖 data 或 app，data 不依赖 app。跨层传递稳定 DTO、领域 ID、命令结果或小型协议，不共享 GPUI 实体。
- `bash scripts/check-architecture.sh` 是三层边界的可执行守卫，CI 会拒绝 core/data 引入 GPUI、core 反向依赖 data/app、data 反向依赖 app、workspace 能力模块缺失，或 `workspace.rs` 再次超过 4000 行。
- Windows 发行与 Debug 运行时都采用便携存储边界：状态库、索引缓存、云端公开资料、崩溃报告和应用生成的临时搜索结果只写入当前 `vclogg2.exe` 所在目录下的 `VCLogg2` 子目录，不读取 `LOCALAPPDATA`/系统缓存目录作为内部落盘根，也不在无法解析或写入该目录时回退系统临时目录。macOS/Linux 继续使用各自的系统应用数据、缓存与临时目录。用户在保存对话框中显式选择的导出目标，以及应用自有临时结果清理触发的系统废纸篓操作，不属于内部落盘边界。
- `crash_report` 在任何单实例、窗口或后台任务初始化之前安装全局 panic hook。每次 Rust panic 都在平台应用数据根的 `VCLogg2/crashes` 下以 `create_new` 写入独立报告，包含版本、平台、进程、线程、源码位置及不依赖环境变量的完整 Backtrace；报告刷新到磁盘后继续调用原有 hook，保留 Debug 控制台输出。macOS/Linux 在首选目录不可用时回退系统临时目录，Windows 只使用 exe 同级便携目录；正常启动只保留最近 20 份。发行构建生成最小行号调试信息，交付脚本按版本生成独立符号包供开发侧崩溃分析留存；PDB 不进入用户分发包或安装目录。
- `app_log` 在其他运行时模块初始化前注册唯一 `log::Log`，以原子等级开关同时控制标准错误输出和内存收集。首次默认值由构建配置决定：Debug 为 Debug，Release 为 Error；用户设置写入 `app_settings` 并可选择 Off/Error/Warn/Info/Debug/Trace。缓冲按 20000 条与 8 MiB 双重上限淘汰旧记录，导出在后台抓取一致快照并写入带版本、构建和本地导出时间的文本文件。
- data 层的 `StateRepository` 独占平台应用数据根 `VCLogg2/sessions/vclogg2-state.db` 的目录创建、SQLite 连接、版本校验、幂等 schema migration 和全部查询/事务；Windows 的平台应用数据根是当前 exe 目录，macOS/Linux 使用系统应用数据目录。app 不再依赖 `rusqlite`。app 层 `StateStore` 只把稳定 data 记录映射为 `AppSettings`、`CompressedRows`、颜色规则、搜索上下文和 `TabResumeState`，默认日志等级与默认颜色标签通过迁移 DTO 传入，不形成 data 到 app 的反向依赖。SQLite 使用 WAL，启动查询和写入都在后台执行；数据库不可用只降级持久状态，不阻塞打开日志。成功打开的多文件批次在单一事务内受路径唯一约束并递增 revision；每个标签另持有与当前界面对应的基准快照，检查点以 `BEGIN IMMEDIATE` 读取最新 revision。基准过期时由 data 仓储只把“基准到本次界面快照”之间实际变化的原始字段覆盖到最新记录，然后在同一事务写入下一修订；回执仅以更高 revision 推进本窗口基准，且基准内容保持为本窗口已提交意图，从而不会把未呈现在本窗口的远端字段误当成本地后续编辑。可空 `custom_title` 随文件会话保存并由幂等字段迁移补入旧库，空值始终回退磁盘文件名。能无损表示为 Unicode 的路径继续沿用旧 TEXT 主键；仅对非 Unicode 原生路径使用带平台标记的无损编码，最近文件、工作区恢复、会话和全局搜索参与偏好共用同一编解码边界；Windows 运行期路径键也直接保留原始 UTF-16 单元，只折叠既有的 ASCII 大小写语义，不让非法代理项经有损字符串化合并身份。文件标记从界面快照、冲突合并到 SQLite 字段始终保持压缩编码，新记录写入带版本前缀的 RoaringTreemap 数据，旧逗号行号列表在 app 适配器读取时直接压入位图，不先展开为行数组。行索引缓存独立于 SQLite 会话身份：Windows 放在 exe 同级 `VCLogg2/index`，macOS/Linux 放在系统缓存目录。
- 每个原生窗口拥有独立 `Workspace` 与 `Root`，共享同一 SQLite 状态库但不共享界面实体。单实例边界在 Windows 使用用户级命名管道，在 macOS/Linux 使用权限为 0600、父目录权限为 0700 的每用户 Unix domain socket；协议分别保留 Windows UTF-16 路径和 Unix 原始路径字节。后续启动不创建第二个 GPUI 应用：空路径请求创建新窗口，非空请求按注册表中的焦点顺序投递到最近激活窗口。Finder/桌面环境的文件 URL 也转换为同一 `OpenRequest`。若该 `Workspace` 正在打开或重载，外部路径在窗口内去重排队，任务结束后复用普通后台打开链路。关闭任一窗口都会先移除对应注册条目、同步抓取最终会话并排队保存。GPUI 使用最后窗口关闭即退出模式，不创建托盘图标或零窗口后台进程。唯一 `on_app_quit` 同步抓取全部仍存活条目的最新标签状态，先等待已关闭窗口和各存活窗口的既有写入，再按窗口创建顺序去重路径，最终用一个事务替换 `last_workspace_files` 并保存文件会话。启动只把该并集清单读入首个空工作区，用户选择单项或“全部打开”后才建立索引。
- 新窗口可接收不可变 `InitialDocument` 列表。标签复制在源 Workspace 同步抓取完整 `FileSessionState` 和临时路径属性；目标 Workspace 等自己的状态库 bootstrap 收敛后，把显式快照作为数据库会话的高优先级覆盖交给普通后台索引链路，因此不共享可变表格实体，也不依赖先写库再读库的竞态。目标重新执行已提交查询并原子安装恢复状态；源标签不卸载。
- 标签移动额外携带源 Workspace 弱引用、源窗口句柄、文档 ID 与捕获状态。目标安装结果通过源窗口上下文回传：失败不改变源；成功后再次从源表格实体派生完整 `FileSessionState`，只有逐字段相等才执行普通关闭链路。若传输期间源状态变化，移动安全退化为复制，避免目标旧快照覆盖或丢弃用户的新操作；每个源文档同时只允许一个未完成移动。发送到“另一窗口”时由注册表选择最近获得焦点的非源窗口，目标通过自己的 Workspace 接收；目标忙碌或同一路径已存在时使用延迟失败回执，避免嵌套更新源实体。
- 文件收藏复用 `file_sessions.pinned`，因此收藏身份与恢复会话一致，不维护第二份路径列表。收藏切换与清空都在后台写入并返回刷新后的收藏/最近快照；最近查询先按固定状态、再按最后打开时间排序。
- 历史清理以当前工作区路径作为运行时保护集合，并在同一事务内仅删除未固定、没有行标记的其余会话；外键级联修正持久化的上一次工作区清单，完成后界面原子替换收藏、上一次文件和最近文件三个查询快照。该操作只清理恢复元数据，不接触日志文件。
- 文件历史详情按用户命令从 SQLite 后台读取完整轻量摘要，不在启动 bootstrap 扫描全部会话。对话框实体独立拥有筛选输入、条目列表、行内删除确认和单一删除任务；删除提交点按数据库 ID 重新读取固定/标记状态，并与打开对话框时的工作区路径保护集合一起判定。成功后对话框和 Workspace 同步替换历史、收藏、上一次文件与最近文件快照，日志文件始终不在删除范围内。
- 应用日志等级、主题偏好、日志呈现默认值、搜索与滚轮策略等应用级选项保存在单行 `app_settings` 表，并通过幂等字段迁移兼容旧数据库。日志等级预览直接调整进程级过滤，取消设置会恢复打开前等级。主题、标签级视图覆盖、搜索开关、结果上限与关闭确认仍沿用各自既有真源和异步提交边界。正文、当前结果和全局结果的纵向滚轮策略收敛到同一捕获入口：原生像素、自定义百分比和固定逻辑行模式都在子表格消费事件前从当前已提交或待绘制位置计算目标，并与 scrollbar 拖动复用同一个待绘制目标；换行列表以统一基础行高和最多 512 条实测高度累计修正求行，列表布局只构造可见范围，不按文件或结果总行数分配行高数组；固定表格用统一行高求行。正文收到普通垂直滚动后立即清除末尾跟随。相邻行预读取继续只围绕组件精确绘制范围维护有界解码缓存，不伪造行节点或改变选择、滚动锚点和减少动态效果语义。自动换行切换会在一次前台更新内转交可见行加载所有权；切回固定表格时不能沿用换行前由隐藏 `DataTable` 留下的旧可见范围，而要按稳定行锚点、锚点相对视口位置和当前区域高度推导固定行高窗口。该窗口在后台可取消地准备，期间继续保留换行 surface 和旧解码窗口可绘制；文档、搜索投影或可见窗口 revision 变化会丢弃并按最新状态重试。只有完整固定窗口准备好后，才在一次前台更新中安装解码行、恢复锚点、切换模式并刷新正文/当前结果/全局结果 surface，既避免固定首帧缺行或空行，也不让文件读取阻塞界面。重新激活标签时同样按目标标签当前的固定或换行渲染器重申请正文与当前结果的可见窗口，并把两个 surface 和窗口失效合并到同一前台更新；关闭活动标签后落到相邻标签也复用这一原子刷新边界，避免已释放解码窗口的 retained 子树一直空白到下一次滚动。文档预览升级、重载、当前结果投影重组、全局分组折叠以及全部打开文件/目录搜索上下文恢复也必须通过同一 owner 交接边界：旧任务先取消，目标后端重申请当前窗口，最后一次通知对应 surface 并失效窗口。
- 日志文档、当前结果投影和全局/目录结果分组的内容替换采用双缓冲提交：旧 delegate 与已解码可见窗口在后台读取目标可见行期间保持可绘制；目标文档或投影、呈现快照、选择与视口、已准备行只在同一次前台更新中整体安装。相同源行号跨文档快照不得复用旧正文；取消或 revision 失效的准备结果不得提交。空结果只有在它本身是最终目标时才直接安装，不允许把“先清空”作为非空列表替换的中间状态。
- 颜色规则由 app 层 `FileState` 按文件持有，并以 JSON 写入 `file_sessions.keyword_color_rules`；标题、标记和已解析规则也在同一状态中作为正文、当前文件结果、全部打开文件结果和目录结果的唯一真源。全局标签定义按稳定 ID 与顺序保存在 `color_labels`，文字色与背景色作为独立字段保存，独立初始化记录使空标签集合与首次默认状态可区分。统一“日志着色”管理对话框同时拥有日志级关键词以及颜色标签的 Input、文字 ColorPicker 和背景 ColorPicker retained 草稿；恢复文档、修改选中行规则或保存全局标签后，规则解析、所选源行解码和匹配器编译都在带 revision 的可取消后台事务中完成，界面提交点只在文档 ID、文档 Arc、标签快照和原规则仍一致时原子安装。区分大小写的字面规则合并成一个保留原顺序元数据的 Aho-Corasick 多模式匹配器，不再让每条可见日志对每条规则独立执行正则，不区分大小写的旧语义继续走兼容匹配器。表格 delegate 只接收不可变匹配器快照，正文、当前结果与全局结果复用同一份；颜色标签覆盖主搜索，页内查找再覆盖两者；数据色是用户标签数据，不进入应用主题。
- 预定义过滤器以规范化 `FilterBranchId(UUID)` 作为唯一且不可变的身份，按顺序存放于 `predefined_filters`；SQLite 的 `filter_id` 与 GPUI `ElementId` 都直接使用 UUID，完整 v5 JSON 保存当前 `FilterSnapshot` 及按服务器隔离的远程引用集合。启动 bootstrap 兼容读取数组、Qt 和 v1–v4 JSON：合法旧 UUID 原样保留，只有缺失或非法时生成一次新 UUID；相同 UUID 才折叠并合并引用，不同 UUID 即使五个内容字段完全一致也并存。导入按 UUID 追加或三方合并，不删除导入文件未包含的本地项；导出固定为 v5。编辑对话框分别持有名称、匹配值和备注 Input 实体，第一层 Dialog 始终渲染列表，`FilterBranchId` 选择详情；本地详情、云端只读详情、首次分享和逐字段冲突处理收敛为单一二级路由，共用标准 Dialog、滚动边界、`Esc` 关闭和原触发焦点恢复。云端下载、快进与安全合并在替换本地集合后立即发出保存事件，并在重建本地草稿时保留当前二级路由，避免留下内容为空但仍占用对话框栈的模态层。提交只校验必填字段，不再按名称、内容或类型判重；事务替换、跨窗口修订屏障和退出落盘规则保持不变。查询执行仍以完整表达式段避免重复追加，因为重复执行同一段没有意义，但该优化不参与实体身份、持久化或同步判断。搜索补全继续只拆顶层 `|`，其候选去重同样只影响一次查询输入，不合并过滤器实体。
- 云端过滤器客户端与 UI 状态分离：`CloudClient` 在线程安全核心中持有阻塞 HTTP 客户端与一次 401 续权逻辑，GPUI 实体只保留可取消生命周期内的后台任务和不可变 DTO。客户端 UUID 原子写入应用数据目录，服务器地址和显示名称作为公开偏好进入 SQLite，Cookie 与 CSRF 组合只保存到按规范化服务器地址哈希分帐的系统凭据库；公开 profile 不写秘密。首次注册直接提交 UUID 与显示名称，不再读取、校验或嵌入 Ed25519 客户端密钥，也不发送旧客户端使用的密钥 ID、时间戳、nonce 或签名请求头；部署端必须允许未签名的注册请求。

- 本地和远程 UUID 相同时才表示同一逻辑分支。跟踪引用保存服务器、相同远程 UUID、已知修订、所有者与共同基线；派生引用只表达谱系，不参与去重。同步状态由当前、本地基线和远程快照纯派生为未下载、已同步、本地有修改、远程有更新、可自动合并、存在冲突、远端已删除或协议不支持。三方合并对名称、匹配值、正则、备注和共创状态逐字段处理：一侧未偏离基线时采用另一侧，两侧结果相同时直接采用，只有同一字段双方不同改动才冲突；无共同基线、修订倒退或同修订内容不一致按异常冲突处理，绝不覆盖本地。批量下载先应用快进和无冲突合并，再按原顺序进入同一二级冲突页面；“稍后处理”保持该分支不变。合并只更新本地内容和远程基线，不自动提交；已有跟踪分支必须通过“提交本地修改”携带 `baseRevision` 更新，首次分享只接收尚未发布的分支。“另存为新过滤器”生成新 UUID、保留派生来源并清除同分支跟踪。云端详情字段全部只读，历史修订只“恢复到本地”；远端删除保留本地分支并解除对应引用。服务器返回结构化 `revision_conflict/currentRevision` 后，客户端重新读取远端并进入相同三方合并流程，不以错误字符串判定，也不自动重试覆盖。
- 云端服务器通过注册和 `/api/v1/me` 的 `filter-uuid-branches-v1` capability 声明 UUID 分支协议。新客户端把本地 UUID 作为 `clientFilterId`；支持协议的服务器用它作为远程主键，同所有者按基线修订更新、其他所有者返回身份冲突，同 UUID 同内容保持 `no_changes`。未声明 capability 的旧服务器仍可浏览、缓存和下载，但客户端禁用首次分享与远程提交。服务端继续接受非 UUID `clientFilterId` 的旧客户端流程；内容相同但 UUID 不同的记录在普通和管理员路径都允许共存。
- 应用更新入口没有 retained 状态或后台任务：帮助菜单使用标准 `PopupMenuItem`，点击后只调用 GPUI 的系统 URL 打开能力访问项目 GitHub Releases 页面。客户端不读取 Releases API 或自建更新源，不生成下载暂存文件，不复制自身，也不启动独立安装助手。发布流水线只生成三平台发行包；Windows 未配置签名时在 ZIP 名称中标识 `unsigned`，选择 Artifact Signing 或 PFX 后在压缩前后及上传前验证 Authenticode 签名与 RFC 3161 时间戳。
- 关闭标签会同步生成带版本号的 `TabResumeState`：正文选择与正文视口分离保存；视口以首个可见源行、该行顶边相对视口顶部的像素位置、横向偏移和末尾标志表达；当前文件结果另存可见性、稳定源行选择、结果下标回退和独立视口；活动区域、末尾跟随及标签级自动换行一并进入同一快照。重新打开在任何文件 I/O 前先用路径和显式空 `LogDocument` 同步注册稳定 `DocumentTab`、TableState 与虚拟列表实体；后台优先用严格验证的缓存偏移读取保存视口锚点前后最多 200 行，缓存不可用才读取最多 1 MiB / 200 行的安全头部预览，再建立完整索引并在同一实体中依次换入。分段预览只持有该窗口正文，但 `segment_start_row` 让表格选择、标记、行号与会话始终使用全局源行号。打开中或预览标签关闭后，后续结果必须同时匹配路径与文档 ID 才能提交。会话选择、标记和恢复快照在预览范围外时保持待恢复，完整文档和已提交查询结果都安装后只经过一个 `apply_tab_resume` 入口恢复，不再用选中行居中代替视口；旧会话由 `selected_row` 与查询文本迁移为兼容快照。关闭写入在窗口内严格串行，后一提交以同一路径前一回执作为合并基准；立即重开优先使用尚未落盘的最新内存快照。完整阶段失败会保留可浏览预览并允许重新加载；搜索、页内查找、按行定位、末尾跳转和跟随只接受 Ready 文档。
- 当前文件、全部打开文件和每个规范化目录是彼此独立的 `SearchSessionState`。当前文件上下文随文件会话持久化；全部打开文件与目录上下文将查询、大小写、正则、结果模式、可见性、上下文级自动换行、目录选项、分组折叠、按路径压缩的源行选择、活动稳定行和视口锚点写入版本化 `WorkspaceSearchState`。v2 以无文件系统 I/O 的词法规范化路径作为目录键，按最近使用顺序最多保留 20 个目录会话；v1 的单目录字段显式迁移为首个会话。默认大小写与正则只初始化新会话，之后范围切换完整安装目标会话。目录、分组、选择、活动行和视口使用与 SQLite 相同的无损原生路径编码，非 Unicode 文件不会因 JSON 字符串化而合并身份；选择集合直接写入带版本前缀的 RoaringTreemap 编码，不逐行枚举，旧范围数组继续兼容读取。全局和目录范围允许空查询：匹配器为空、匹配集合为空，显示集合仍由结果模式是否包含同路径打开标签的标记决定。目录后台只保留有匹配或与打开标签同路径的候选快照，安装到表格前剔除零行分组。搜索范围只选择一个上下文投影到共享结果显示器：离开全部打开文件或目录范围时同时捕获领域状态和当前可见窗口的有界解码快照，进入范围时直接恢复，不重新扫描搜索、不读取日志来定位活动行，也不改变上方日志文件；只有用户主动点击或键盘确认结果行才发出打开文件和定位命令。进程重启不保存可能巨大且过期的结果正文；启动恢复流程可按既有持久化策略重建，而普通范围切换绝不触发搜索。重新搜索后若活动或视口锚点已不在新结果中，优先在同一文档按源行距离选择最近结果，文档本身也消失时再按原显示位置选择最近的可见结果；等距时保留前一行，多选集合仍只保留新投影中真实存在的行。因此各范围不会互相覆盖，且文件内容变化时不会展示旧结果。打开新文件只更新下一次“全部打开文件”搜索的参与集合和搜索 revision，不清空已完成的全部打开文件或目录结果快照；已完成的全部打开文件视图只投影实际参与该次搜索的文档，新加入文件要到下一次执行搜索后才进入结果。
- 自动换行的所有权跟随结果上下文：正文和该文件的当前文件结果使用 `FileViewState` 对应的文件会话换行值，全部打开文件与每个目录会话各自使用 retained/persisted `word_wrap`。切换标签、搜索范围或重开应用只恢复目标上下文自己的值，其他文件或搜索范围后续切换自动换行不会污染它。
- 主界面固定为上下两个可调整显示区。`Workspace` 只创建一份上方 `log_viewer` 和一份下方 `search_results_viewer`；每份共享 retained 宿主拥有稳定的 surface、焦点身份和文字选择作用域。标签或搜索范围切换只替换宿主后方的文档/结果投影与不可变呈现快照，并在同一 Workspace 更新中一次刷新，避免中间混合帧。表格 delegate 仍是虚拟投影和交互模型，不是文件或搜索类型专属 panel；隐藏标签和历史目录会话不持有显示 surface。全部打开文件与当前目录会话额外各保留最近一次可见窗口及 overscan 的有界解码快照，切回时把它与投影、选择和视口一起安装；它不扩展为完整结果正文缓存。
- 行选择、搜索提交/清除、结果模式、标记和呈现选项变化会替换当前窗口唯一的延迟任务；活动状态连续 1.5 秒不再变化后才抓取并写入检查点。切换标签和关闭标签仍即时抓取旧标签，避免合并任务取消时丢失最后状态。
- `Root` 是每个窗口唯一的顶层组件，统一负责弹层、通知和焦点恢复。Workspace 在普通内容与 Root 前景层之间安装逐窗口、逐坐标的透明指针命中哨兵：后绘制的 Dialog、Sheet、Popover 或其他 occluder 覆盖当前坐标时，先让前景处理事件，再阻断后台滚动条等原始监听器；搜索面板拖拽入口同时以顶层 hitbox 为准，不能穿过遮挡启动。标题栏提供常驻清除按钮并调用当前窗口 Root 的批量关闭链路，不影响其他窗口。
- 设置对话框打开后以自己的 retained 后台任务读取系统索引缓存目录，只枚举 `.vclog-index` 与严格命名的暂存文件。手动清理先捕获路径、大小和修改时间，删除每项前重新读取 metadata 并只删除完全未变化者；清理与正在完成的原子缓存写入可以并发，变化或占用文件安全保留。目录揭示先后台创建目标目录，再调用 GPUI 平台能力，不经过 Shell 字符串拼接。进程级原子门保证启动后只调度一次延迟自动维护；普通缓存超过 90 天、暂存超过 24 小时会进入候选，再按最旧优先把普通缓存压到 512 MiB，所有删除仍复核原快照。
- Windows 二进制通过包级 `build.rs` 只为 `vclogg2` 链接目标预留 8 MiB 主线程栈。GPUI 首帧会在平台主线程构造完整的类型化元素树，默认 PE 栈预算不足会在窗口首次渲染时溢出；扩大的是虚拟地址预留，不改变业务任务的后台执行边界。
- 可重复日志行、标签页和结果项使用文件身份与源行号构成稳定身份，不使用可变列表下标作为长期身份。
- `LogDocument` 是后台建立后原子安装的只读领域快照，不拥有高亮、选择、选词、字号、行高、自动换行或标记等显示状态。界面和结果 delegate 只保存“虚拟行到文档 ID / 源行号”的投影，并在虚拟列表请求可见行时读取正文，再按当前不可变呈现快照组合样式。安全预览的驻留内容受字节和行数双重限制，metadata 仍保留源文件真实大小；一条超长首行最多显示 1 MiB，不会为寻找换行越过边界。完整索引缓存缺失时通过固定 4 MiB 缓冲区位置读取源文件，同一遍流式建立行偏移、最长行信息和 SHA-256 分块摘要；跨块保留 CRLF、UTF-16 code unit 与传统多字节编码的解码状态，扫描结束再次校验大小、修改时间与平台强身份，因此内存不随文件大小增长，外部截断或覆盖只会让后台打开失败。安装后的完整文档不长期映射源文件，默认持有原文件句柄、建索引时捕获的每 4 MiB SHA-256 和最多 8 MiB 的已验证显示块缓存。目录搜索文档完成扫描后切换为瞬时句柄模式并立即释放句柄；后续可见块按路径和平台强文件身份重新打开、校验、位置读取后关闭，且不写入文档级原始块缓存，因此大量命中文件不会各占一个长期文件描述符或按已浏览文件累计原始块内存，打开标签仍保留稳定句柄。可见行、复制和导出通过操作系统位置读取取得所需块，摘要一致才暴露字节；已经缓存的原始块在外部原地覆盖后仍保持旧快照，尚未读取而已变化或截断的块被记为不可用，不会混入新内容或访问失效映射；暂时打不开、元数据暂不可读或位置读取失败不会毒化块状态，后续请求仍可重试同一快照。`line_preview` 只组装显示上限附近的逻辑字节；搜索为每个并行行区间持有一个当前校验块游标，块不进入文档长期缓存，也不对每行获取共享锁。编码检测按 BOM、已知二进制签名、无 BOM UTF-16 启发式、控制字节、UTF-8 与 chardetng 传统编码依次决策；LF、CRLF 和独立 CR 均由同一编码感知分行器建立偏移，文件以换行结束时保留末尾空行，UTF-16 使用双字节分隔符，Binary 使用固定 16 字节行。显示、搜索、高亮和导出都从同一快照解码，避免视图与搜索语义漂移。完整索引以系统缓存目录中的原子文件持久化，行起点按递增差值 varint 压缩；只有文件大小、修改时间及平台强身份全部一致时才复用：Windows 使用卷序列号、128 位文件 ID 与 USN，macOS/Linux 使用设备号、inode 与 ctime。内存行起点构建器按文件最大偏移直接选择 `u32` 或 `usize`，常规文件从扫描到不可变 Arc 都保持每行 4 字节；增量追加只有真正跨过 4 GiB 边界时才升级现有偏移，避免先建立原生宽度数组再压缩的峰值副本。缓存缺失时先发布完整文档，再由后台任务写入共享行起点 Arc，不复制正文。行索引同一次顺序扫描记录最长字节行与最长显示列：UTF-8 沿用旧版的字节列语义，制表符推进到下一个 8 列制表位，首行 BOM 和行尾 CR 不占宽度；非 UTF-8 文本按解码字符计算显示列。纯增长增量路径只接受已有非空 UTF-8 / UTF-8 BOM 快照，通过同一位置读取遍历验证全部旧分块、生成新摘要，并只从旧末行起点重算行偏移；结尾分隔符会回退一行，正确处理原文件末尾 CR 与新首字节 LF 合成 CRLF。其他编码和空文件增长回退完整重建，以重新检测编码；核心不再依赖内存映射。空文件使用显式空快照。
- 搜索范围由 Workspace 在当前标签、多标签和目录之间单点拥有。目录配置保留根路径、文件后缀过滤的启用状态与表达式、递归及隐藏目录策略；多个后缀以 `|` 分隔并按大小写不敏感的文件名末尾匹配，关闭过滤时接受所有文件。枚举拒绝符号链接递归并隔离不可读目录。候选路径通过与普通打开相同上限的准备工作线程创建临时 `LogDocument`，共享一次编译的匹配器和协作取消令牌；取消既中止正在建立的索引，也阻止并行调度器继续领取剩余候选，只把实际命中文档原子安装到全局虚拟结果。临时结果使用与标签 ID 不相交的高位身份；点击结果后按路径复用普通打开链路，完整索引到达时再提交源行定位，因此目录扫描不会制造标签或文件会话。
- 目录搜索完成后把每个命中文档投影成稀疏源行快照：共享完整文件字节身份和分块摘要，但行索引只保存命中源行的起止偏移与压缩源行集合，不让少量命中的大文件继续保留完整行起点数组。同路径标签仍打开且内容摘要一致时，结果组改用标签的完整文档读取动态标记行；标签关闭后回到只含搜索命中的目录快照。普通导出只读取投影行；只有按时间戳合并这种明确需要命中行之外上下文的后台操作才临时重建完整行索引，并在内容摘要与搜索快照不同后整笔拒绝。结果模式因此只决定要显示哪些压缩源行，文件对象不承载选择、折叠、换行或高亮状态。
- 正文、当前结果和全局结果的固定/换行虚拟列表都只在 UI 线程发布“当前可见范围 + overscan”的稳定行键请求；磁盘读取、4 MiB 分块校验、解码和预览截断在后台完成，结果携带窗口 revision，滚动、投影变化或文档替换后迟到结果不能安装。`VisibleLineStore` 只保存当前准备键与最多 32 MiB 的解码预览，渲染查询从不回退同步文件 I/O。预算按可见优先顺序公平分配给当前稳定行键，并以解码字符串、tab 展开文本和稀疏 tab 映射的实际驻留成本为准；超出单行份额时先在 UTF-8 字符边界裁剪并保留省略标记，因此表示膨胀既不能突破总预算，也不会让后续可见行静默空白。后台返回前，行处于未安装状态；路径重开、身份校验或分块摘要失败则安装带类型标记的“源快照不可用”呈现，固定与换行列表不再把它混同为仍在加载的空白，也不让错误说明参与搜索、颜色或日志级别高亮。固定行高 delegate 与换行 Workspace 是同一列表互斥的任务 owner；模式切换先丢弃两侧 retained task 并推进窗口 revision，再由新 owner 重发当前稳定行请求，因此旧后端不会继续占用源 I/O，新后端也不会继承只有请求而没有结果的 pending 窗口。每个后台窗口任务使用 task-local `LinePreviewReader`，按文档最多复用当前验证块；目录结果因此能让同块相邻命中共享一次打开/读取/校验，同时不会把浏览过的块留在稀疏文档上。高亮、选择、选词、字号、行高、换行和标记仍在预览安装后由当前呈现状态组合。
- 每个可见行窗口请求还携带独立的协作取消标志。滚动、投影变化、文档替换、换行后端切换或列表销毁都会使旧请求在读取下一行前停止；revision 只负责最后的提交一致性，不再承担阻止无效源 I/O 的职责。普通结果投影会剔除已不可达行；全局分组折叠/展开则先在不修改当前投影的计划上准备目标可见窗口，随后一次安装预览、替换投影和恢复稳定行锚点，等待期间 retained surface 继续绘制旧帧。标签失活时释放正文与当前结果的解码窗口和两种布局后端任务，只保留选择、标记、视口等轻量呈现状态，因此可见正文驻留量不随打开标签数线性增长。再次切换到文档标签时，旧标签继续绘制，目标标签的正文与当前结果可见窗口在同一个后台帧中预备；文档身份和两个窗口 revision 都仍匹配后，前台才一次安装两份预览、切换活动标签并刷新 retained surface，中间不会提交空列表。
- 复制、颜色关键词收集、页内查找和结果导出等明确需要完整正文的操作只在后台执行，并在每个文档的单次操作范围内持有 task-local `LineReader`。它与可见预览读取器共享“最多一个当前校验块”的读取游标，使同块内相邻或稀疏结果行复用一次位置读取，同时既不把完整行文本聚合到内存，也不把目录结果浏览历史写回文档级块缓存。兼容单行 API 继续使用打开文档自身最多 8 MiB 的热块缓存；调用方必须按所需生命周期显式选择，不能把任务 reader、高亮、选择或布局状态放进 `LogDocument`。
- `TableState<LogTableDelegate>` 继续拥有固定行高虚拟化与纵横滚动，但不再拥有日志的可见当前行样式：delegate 内的 `LogTableCursor` 保存当前虚拟行，Workspace 按区域焦点完成键盘导航，再借用 TableState 滚动句柄定位。指针、键盘确认或显式结果跳转通过 TableEvent 交付一次语义选择，随后在同一次更新中清除组件内部整行选中态；会话恢复直接写入 delegate 的稳定活动行和压缩选择，不发 TableEvent，因而不会误触发文件激活或日志定位。压缩 `RowSelection` 保持不变并作为正文列选区的唯一绘制来源，因此单选与多选不会再把标记列或行号列染色。delegate 使用所选等宽字体在 GPUI 文本系统中的实际 `ch` advance 与索引最长显示列生成消息列宽；全局结果只在不可变分组快照安装时汇总一次各文档的最长列，布局查询不再随重绘遍历全部文件。正文、当前结果和全局结果各自保留独立 FocusHandle、压缩行选择与滚动状态，`LogRegion` 是窗口级命令归属的唯一真源；鼠标按下、Tab 聚焦和结果跳转更新该归属，复制、全选、标记、颜色标签与页内查找不再从搜索范围推断目标。普通日志页面的文字参与者统一注册到 gpui-component Root 实际激活的默认文字作用域；区域隔离由真实指针命中、独立 FocusHandle 和 `LogRegion` 完成，不创建只会被 Root 普通页面忽略的自定义作用域。重复行使用 `LogRowKey`（文档 ID + 源行；全局文件标题使用文档 ID）作为稳定身份，不把可变表格下标持久化。
- `GlobalSearchTableDelegate` 复用同一带 revision 的 `RowSelection` 压缩区间状态机，组标题只占虚拟布局槽而不成为领域选择。状态栏的选中数按“选择 revision + 布局 revision”缓存；`Ctrl+A` 只保存覆盖整个扁平虚拟空间的一个区间，领域投影时再跳过标题和折叠组，因此百万级结果不会逐行建集合。折叠切换前按稳定 `(document_id, source_row)` 捕获选中行与活动行，重排后只恢复仍可见者；选择区间与有序文件布局通过单次归并扫描生成每文件 `CompressedRows`，不会对每个文件重新遍历全部选择段。复制、标记与颜色标签等命令也先按当前分组顺序取得这些压缩集合，不建立与选中行数等长的 `(document_id, source_row)` 数组；整行复制从 delegate 捕获与屏幕内容一致的不可变文档快照，在后台逐行解码并拼接，界面线程只提交最终剪贴板值，后续复制会协作取消旧任务的剩余解码并以 revision 拒绝迟到回写。结果模式、标记和颜色规则引起重组前，delegate 把选择压缩为每文件 `CompressedRows`，重组后只恢复仍可见的源行。整行复制保持当前分组顺序，批量标记按文件更新各自 Session；颜色标签先验证所有源行属于同一文件，拒绝跨文件含混修改。

- 标记、颜色规则、搜索结果和结果模式修改都在单次 Workspace 更新中捕获选择/视口、生成不可变标记与高亮快照、更新三个区域 delegate、恢复稳定身份后统一通知。菜单栏、标题栏、快捷键和标准 ContextMenu 复用同一领域方法；PopupMenu 只持有打开时的稳定文字或行上下文，文档/结果失效时由领域方法再次校验并安全退出。A051 是始终存在的独立标记列：搜索命中使用 danger 实心标记，用户标记使用 warning 实心标记，两者重叠时由同一圆内 135° 红黄分区表达，光晕与轮廓沿用同类主题 token。选择背景只覆盖正文列；单行具有完整上下边界，相邻多选压缩为不含内部边界和行分隔线的连续段，离散范围各自成段。页内查找、颜色标签、已提交搜索保持严格覆盖优先级；日志级规则为整行提供用户配置的文字色与背景色，选择和片段高亮仍按原优先级覆盖对应区域。
- 换行尺寸状态同时从最多 4096 个实测行构建按行排序的累计高度修正，前缀高度和指针命中通过二分定位而不从文件头线性扫描。尺寸提交前抓取“首个逻辑行 + 行内像素偏移”，提交后按新前缀恢复同一锚点。覆盖在同一 `SparseVirtualListScrollHandle` 上的 `LogicalVirtualScrollHandle` 向 gpui-component `Scrollbar` 暴露固定的 `逻辑行数 × 基础行高` 轨道，并在读取/拖动时以当前行内比例双向转换真实像素；精确末屏单独映射实际最大偏移，因此新测量不会改变已抓住滑块代表的逻辑位置。
- 标签命令菜单由触发标签的文档 ID 闭包绑定，不读取可能在菜单打开后变化的活动下标。标签正文的 `ContextMenuExt` 命中层与省略号按钮复用同一个 PopupMenu 构建器，保留组件的焦点恢复且不遮挡后缀按钮。批量关闭先同步捕获目标标签会话，再一次过滤文档、全局参与集合和已提交全局分组；活动标签仍存在时按 ID 恢复，否则按关闭前索引夹取相邻标签。路径复制与平台文件揭示同样只按触发文档 ID 解析。
- 源日志是只读输入。标签菜单只允许关闭、重排、跨窗口传输、复制路径、揭示位置和修改显示名称，不提供删除、移动或重命名源文件的能力；应用生成的临时搜索结果清理则在提交点再次校验其直属受管目录和普通文件类型后才调用系统回收站。
- 标签自定义名称由 `DocumentTab` 持有并通过同一 `FileSessionState` 检查点持久化；显示标题是自定义值或磁盘文件名的单一派生结果。重命名与恢复在一个提交中同步标签、活动窗口标题和已有全局结果组标题，不改变文件身份、路径或搜索快照。
- 窗口内标签拖放负载只携带稳定文档 ID、显示标题、源 Workspace 弱引用与预览位置；`Workspace` 是顺序的唯一写入者。放置时先按 ID 移出并插入目标槽，再按活动文档 ID 重算下标，同时重排已提交全局结果组；文档实体、索引快照和表格状态不重建。Windows 后端在鼠标按下后调用 `SetCapture`，因此源窗口会继续收到视口外的拖动与松开事件；跨窗口协调器把源局部坐标乘源缩放比转换为物理屏幕坐标，再按各目标窗口缩放比换算局部坐标，与 prepaint 记录的标签边界求插入下标。若释放点不在任何 VCLogg2 窗口内，则按 GPUI 显示器边界在释放点附近创建可见的新窗口，并继续使用同一成功回执协议。目标窗口只接收完整 `InitialDocument`，真实日志路径不会成为系统拖动负载；取消、源窗关闭和应用退出都会清除目标提示而不卸载源标签。新顺序通过 `save_workspace` 的单事务路径立即保存，退出 flush 仍作为最终一致性屏障。
- 行号与正文分隔线属于标签页呈现状态，由同一视图选项快照同步到正文和结果两个 DataTable delegate。隐藏行号会重建列布局，但不改变源行身份或选择；分隔线只使用主题边界 token 绘制在正文单元格中。
- 日志文字色与日志背景色属于按浅色/深色主题分别保存的应用级外观；未自定义时回退到两套产品主题各自的日志专用默认色。“跟随系统”只选择当前生效的一套，不合并两套草稿。固定行高 DataTable 和可变行高虚拟列表都从同一设置快照解析文字色与表面 token，并同步覆盖日志、单文件结果、全部打开文件结果和目录结果；搜索命中、页内查找、来源不可用、选择与日志级别着色仍按既有优先级覆盖基础文字或背景。
- 行号栏几何与颜色属于应用级外观：40–160px 是旧版可配置物理列宽契约，不随日志字号缩放；可空的 `#rrggbb` 用户颜色在渲染时回退到当前主题的弱前景与低对比度底色。固定行高 DataTable 和可变行高虚拟列表都让正文分隔线只属于正文单元格、独立行号分隔线只属于行号单元格，并同步覆盖日志、单文件结果和全局结果。
- 行标记由对应 `DocumentTab` 持有源行号集合，正文与结果表 delegate 共享不可变快照；单行和多行标记使用同一个批量语义：目标全部已标记时统一取消，否则补齐未标记项。重新加载时会剔除超出新文件范围的标记。结果模式同样属于标签页状态，由单一派生步骤将有序匹配行与标记行合并、去重或筛选，再原子刷新结果表，并按仍存在的源行恢复结果选择。
- 打开和搜索由 GPUI background executor 执行；搜索扫描持有显式取消令牌和共享一致性进度快照，新任务、清除、重新加载或关闭文档会中止失效扫描。窗口在搜索期间按固定间隔采样快照且只在数值变化时刷新，完成时再通过文档 ID / 全局轮次 revision 拒绝迟到结果。
- 已提交搜索命中以共享 `RoaringTreemap` 保存源行号；结果模式把用户标记直接并入新的压缩集合。单文件表通过 `select` 把虚拟行映射为源行、通过 `rank` 恢复选择；全局表仅保存每个文件组的累计起点，按需计算组头或压缩集合中的结果行，不再构造与全部命中数量等长的 `FlatRow`。全局页内查找只克隆每组文档和压缩集合，导出按迭代器逐行解码，因此搜索完成后不会在 Workspace、表格、查找和导出层重复展开命中数组。
- 全局结果重组前同时捕获首个可见逻辑行的稳定身份和被视口裁掉的像素余量；新分组安装后先映射稳定身份，再用 gpui 虚拟列表的统一行高还原绝对偏移。若首行已被过滤则回退到所属分组标题，若尚无布局测量才回退为严格顶对齐。
- AppShell 是外部文件拖放的单一命中区域；平台 `ExternalPaths` 在界面提交点过滤文件夹并保留原顺序，然后直接进入与文件选择器相同的 `begin_open_paths` 后台准备和原子安装流程，不维护第二套拖放专用文档状态。`Workspace` 只保留窗口级覆盖层可见状态；零绘制 Canvas 在 paint 阶段按 GPUI 契约注册下一帧 `FileDropEvent` 监听，并由 `Entered / Exited / Submit / Ended` 精确切换状态，拖动停留不会超时消失，离开、取消或提交也不会遗留覆盖层。
- 主进程只在进入 GPUI 事件循环前读取一次 `args_os()`；可执行文件之后的路径按原顺序转换为不带显式会话覆盖的 `InitialDocument`，待首个 Workspace 的状态 bootstrap 完成后复用普通打开链路并查询已有会话。跨窗口复制/移动仍携带显式会话快照作为高优先级覆盖。命令行、文件关联、文件选择器、最近记录、拖放和跨窗口传输最终共享同一加载状态机与迟到结果校验。
- 全局搜索以提交时的已打开标签顺序捕获不可变文档快照，每个文件在线程作用域内并发扫描，界面只汇总进度。可见全局分组与后台待提交结果双缓冲：任何文件完成都不发布部分分组；全部文件结束后才一次替换 `GlobalSearchTableDelegate`。取消、无效正则、关闭目标文件或新轮次到达都保留上一份完整结果。
- 全局搜索参与集合在运行期由 `Workspace` 以文档 ID 持有，选择对话框只编辑 retained 草稿，确认后与当前标签集合求交并一次提交；同时按规范化文件路径把每个已见文件的布尔偏好幂等写入 SQLite。再次打开已见文件时恢复其偏好，未知新文件默认加入；关闭文档同步移除运行期 ID，提交搜索时只按标签顺序捕获已选择文档，空集合显式禁用执行。
- 工作区搜索恢复同时重建“全部打开文件”和“目录”两份最后完成的查询，而不是只恢复启动时可见的范围；后台按当前范围优先串行执行，非当前范围只提交到自己的 `SearchSessionState`，不切换共享搜索面板。全部打开文件上下文额外持久化上次参与查询的无损路径列表，因此重启后即使对应文件尚未作为标签打开，也能从只读稀疏快照恢复结果、折叠、选择、活动行、视口、换行和关键词高亮；旧版上下文没有路径列表时回退已保存的参与偏好。
- 全局或目录结果指向未打开文件时，点击结果行先用一个完整前台帧提交结果表的活动行与选择，再在下一帧启动普通文件打开与完整索引链路；本次结果行从文件恢复的第一帧起就覆盖该文件上次关闭时保存的选中行，待跳转请求会穿过中间 Preview 安装而保留到 Ready，目标日志行直接进入文件首个 Ready 帧的预读取，并在文件会话恢复后一次安装当前搜索匹配器、命中行、选择和居中视口。结果投影的恢复与后台替换只直接维护 delegate 的稳定行状态，绝不发出 `SelectRow` 导航事件覆盖本次点击。文件内容身份不一致时拒绝跳转并要求重新搜索，不能只打开标签或把旧行号应用到新内容。
- 全局结果 delegate 把文件标题与展开的源行扁平为一个 DataTable 虚拟索引空间。文件 ID 和源行号构成稳定行身份；有结果的标题行只改变本组折叠状态，零结果标题通过文件 ID 激活目标标签，命中行则继续定位具体源行。目标属于另一已打开文件时，Workspace 在后台预取目标视口或目标行周围的完整首帧，把可见正文、行选择、视口和活动标签一次提交；准备期间继续显示原结果与日志 surface，不发布空白目标标签。零结果目录标题指向尚未打开的文件时，`Opening` 与 `Preview` 阶段同样保留原 surface，直到目标达到 `Ready` 且首帧已准备后才激活；目录命中定位复用同一提交边界。布局快照除累计组起点外只保存展开且非空的结果组索引，标题附近的拖选命中通过二分直接定位前后结果，不逐行穿过连续折叠组。`Workspace` 独立保留每个参与文档的原始匹配集合；全局结果模式或 Session 标记变化只重组显示集合，不重新扫描。重组前捕获选中领域行、首个可见领域行及其像素余量，提交后按文件 ID/源行映射，并用虚拟列表行高还原精确偏移。
- 结果导出在界面提交点捕获不可变 `LogDocument` 与源行号集合，后台逐行解码并写入固定容量缓冲，不把全部结果正文聚合到内存。当前文件只写日志正文；普通全局结果按已提交标签顺序写非空分组，并以完整路径作为组标题。时间戳合并为每个文件维护一个游标与最近已解析时间，行首按无时区的月日、时分秒、微秒打包；续行先在上个结果之后反向寻找时间戳，再继承游标时间，仍未知时向后探测。最小堆只持有每个文件当前一行，以时间戳、标签顺序、源行号稳定归并且不写分组标题。用户目标先在同目录创建唯一暂存文件、刷新并同步到磁盘，Windows 已有目标由 `ReplaceFileW` 原子替换；失败清理暂存文件且不破坏旧目标。新标签命令在唯一临时目录完成同一写入协议后才进入普通索引/标签安装链路，临时路径由 Workspace 排除在最近文件、会话检查点和退出恢复之外。
- 临时结果生命周期不依赖 SQLite：文件历史后台只扫描平台临时结果根直属且名称为 `vclogg2-search-*` 的目录和普通文件，形成轻量路径/大小/修改时间快照；Windows 根目录是 exe 同级 `VCLogg2/temp`，macOS/Linux 是系统临时目录。打开保护集合从应用级窗口注册表汇总所有 Workspace，而不是只查看发起对话框的窗口。单项与批量清理在提交点再次限制为该临时路径形状，再逐文件调用系统回收站；成功后仅以非递归方式删除空父目录，避免清理命令扩大到临时根或其他应用数据。
- 文件历史的数据库摘要在状态库互斥锁内执行一次被动 WAL checkpoint 和 `file_sessions` 计数，释放连接锁后再读取主库、WAL 与 SHM 三个明确 sidecar 路径的 metadata 并饱和求和；统计不扫描日志文件或索引目录，也不让缺失的瞬时 sidecar 阻断历史对话框。
- 文件关联不再由设置页运行时修改。Windows Release 采用纯便携交付，不附带仓库中保留的自部署安装脚本，也不自动写入 `Applications\vclogg2.exe`、ProgID、`RegisteredApplications`/Capabilities 或 `OpenWithProgids`；macOS `Info.plist` 声明受支持文档扩展并由 Launch Services 注册，Linux 安装器写入用户级 `.desktop`、图标与 MIME 列表。平台传入的路径或文件 URL 都复用单实例转交和普通打开状态机。
- 自定义打开目录命令同样不经过 Shell 字符串：设置页只持久化最多 2048 个字符的原始命令，提交时由应用内解析器识别单/双引号边界，把首项作为可执行文件、其余项作为 `Command::args`，再替换目录和文件占位符；没有占位符时只追加一个目录参数。子进程以目标目录为工作目录、关闭标准流并在 Windows 隐藏控制台，解析或启动错误回到触发窗口通知。空设置仍使用 GPUI 平台的系统打开能力。
- 云端公开目录缓存位于平台应用数据根的 `VCLogg2/cloud/directory-cache`，Windows 因此使用 exe 同级便携目录，macOS/Linux 使用系统应用数据目录。文件名由标准化服务器 URL 的 SHA-256 派生，内容只含公开过滤器 DTO、查询/排序分页键与抓取时间。在线目录成功优先返回真实响应，缓存写入失败不会遮蔽结果；网络或服务请求失败才读取缓存。离线读取对所有保留分页按 UUID 与修订去重，在本地执行查询、排序和分页，并把界面切成显式只读状态；缓存只允许下载或合入严格晚于本地基线的修订，不能写远程，也不能回退本地基线。会话 Cookie、CSRF 及草稿从不进入该缓存。
- 成功搜索会把与扫描器同源的已编译 `SearchMatcher` 安装到正文和结果 delegate。虚拟表只为当前绘制行计算非空 UTF-8 字节范围；选词、颜色与主搜索的重叠区间通过起止事件和优先级堆以 O(匹配数 log 匹配数) 合成，再用 GPUI `StyledText` 与主题 token 呈现，不对每个分段重新扫描全部候选。仅标记但未命中的结果行不会产生高亮。日志级规则同样只在当前绘制行按 ASCII 单词边界匹配，默认规则依次为 `INFO`、`ERROR`，后置规则覆盖前置规则；应用级规则 JSON 与启用状态保存在 `app_settings`，解析后的不可变样式快照同时供固定行和自动换行呈现使用，不写入 `LogText` 解码缓存。匹配行使用规则自己的文字色、背景色和左侧色条，不占用独立标记列。选择背景只覆盖正文列，用户标记始终由标记列表达。全局结果 delegate 复用同一规则快照，避免三个视图语义漂移。
- 末尾跟随是每个标签独立保存的显式状态。窗口只对当前活动、完整索引就绪且开启跟随的文档做低频元数据采样；文件变化后把旧快照交给核心刷新。完整文档建立时除头尾各最多 64 KiB 的快速样本外，还保存旧前缀每 4 MiB 的 SHA-256；只有新文件更大、快速样本一致且全部旧前缀块逐一匹配时，核心才复用旧行起点并只扫描新增字节。任一中间块改写、截断、替换或读取边界异常都回退全量重建；成功追加形成的新快照重新计算覆盖完整新文件的分块摘要。两条路径都在后台形成新快照并通过文档 ID 与 revision 拒绝迟到结果，界面最后原子发布、恢复查询并定位末行。手动 `F5` 始终全量重建；用户把正文视口移离末尾或点击结果导航时关闭跟随。持久索引复用已有强文件身份。
- 主题颜色、字体、间距和控件大小全部来自 `cx.theme()`、rem helper 或组件 Size API。窗口初始物理尺寸是唯一经过说明的固定像素边界。
